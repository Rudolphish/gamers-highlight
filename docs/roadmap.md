## Phase 2：展開判断

このフェーズで「他の友人グループにも展開するか」を判断する。判断材料：

- 自分の友人グループで実際に投稿・検索の習慣が定着したか
- 「あのスクショどこだっけ」という元々のペインが解消されたと言えるか
- 運用コスト（Supabase/R2/Vercelの無料枠内で収まっているか）

展開しない判断であれば、個人・身内用ツールとして磨き込みを継続する（Phase 3以降は保留）。

## Phase 4：収益化検証（展開する場合）

EpicSnapで検討していた「保存数制限＋Stripeサブスク」型を叩き台にしつつ、Powderの事例（一般ゲーマー向け課金からの撤退）を踏まえて慎重に検証する。

- [ ] 料金モデルの仮説検証（フリーミアムか、コミュニティ管理者向けB2Bプライシングか）
- [ ] Stripe連携によるサブスクリプション管理
- [ ] 課金導線のUX設計（保存容量制限など、体験を損なわない形での提示）

一般ゲーマー個人への定額課金は懐疑的な材料が多いため、**コミュニティ運営者（Discordサーバー管理者）向けのB2Bプライシング**を優先候補として検証する。

## Phase 6：柱2「これから遊ぶゲームを考える」（長期ゴール）

**個人のウィッシュリスト/ライブラリ管理はSteam自体で完結するため、本アプリでは作らない。** 価値があるのは「グループで共有される」ウィッシュリスト/ライブラリ（このグループが狙っているゲーム、グループ内で今誰が何を遊んでいるか）。データ設計は`Group`単位（`GroupGame`のような新モデルを想定：groupId, steamAppId, status〈WISHLIST/PLAYING/BACKLOG/COMPLETED〉, addedBy, 関連Album（あれば）への参照）。柱1のプレイ状態管理（Phase 5）とも統合できる設計にする。

- [ ] データ設計：グループ単位のゲームリスト（`GroupGame`。ステータス管理、Steam appId紐付け、任意でAlbumと関連付け）
- [ ] Steamジャンル検索（既存の`lib/steam.ts`の検索機能を拡張。ジャンル情報は`appdetails` APIから取得可能）
- [ ] サジェスト機能（まずは簡易ルールベースで着手：グループが過去に遊んだゲームのジャンル/タグから類似ゲームを提案）
- [ ] ゲーム詳細ページ：Steamレビュー表示（公開APIで取得可、APIキー不要）
- [ ] ゲーム詳細ページ：関連YouTube動画表示（**要事前準備**：YouTube Data APIキーの取得）
- [ ] アプデ情報のキャッチアップ（Steam News API。キー不要。グループがプレイ中/積みゲーにしているゲームに絞って表示）
- [ ] グループ内プレイ状況の可視化（「今誰が何をプレイ中/積んでいるか」の一覧。[`ideas.md`](./ideas.md)参照）
- [ ] **ゲーム提案機能**：グループメンバーが「このゲームどう？」とゲームを提案できる。提案には「ゲームページ」（Steamストアへのリンク、関連YouTube動画、価格/セール情報）を表示し、他メンバーがリアクション（興味あり等）できる。一定の反応を集めた（または誰かが確定させた）提案は、グループの「やりたいゲームリスト」（`GroupGame`のWISHLISTステータス）に登録される
  - 前提：ゲームページの中身（Steamレビュー/YouTube動画は本Phase、価格/セール情報はPhase 7）に依存するため、提案機能自体はそれらが揃ってから着手するのが自然
  - データ設計：`GroupGameProposal`（groupId, steamAppId, proposedBy, createdAt）＋`GroupGameProposalReaction`（proposalId, userId, reactionType）を想定

## Phase 7：柱3「狙ってるゲームのセール情報をチェックする」（長期ゴール）

- [ ] グループ共有のウォッチリスト機能（Phase 6の`GroupGame`をWISHLISTステータスとして活用。誰が追加したか・誰が気になっているか等の軽い「興味あり」マークも検討）
- [ ] 現在の価格・セール状況表示（Steam公式APIまたはIsThereAnyDeal APIで取得可能）
- [ ] 最安値表示（**要事前準備**：IsThereAnyDeal APIキーの取得。過去最安値データを持っているため活用が現実的。自前で日次ポーリングし履歴を蓄積する設計は工数が大きいため後回し）
- [ ] 値動きグラフ（IsThereAnyDealの履歴データ、または自前の日次スナップショット蓄積）
- [ ] セール通知のDiscord連携（グループのウォッチリスト内のゲームがセールになったらBotがチャンネルに投稿。[`ideas.md`](./ideas.md)参照）

## 柱2・3を進める上での論点（要判断）

- 柱2・3は、現在の「友人グループ内スクショ整理ツール」という狭い立ち位置から大きく踏み出す拡張になる。vision.mdの「非ゴール」（周辺機能を広げすぎない）との兼ね合いをどう考えるか、Phase 2の展開判断を待ってから着手するか並行して着手するか、方針を決めておくとよい
- YouTube Data API・IsThereAnyDeal APIはいずれも無料枠はあるが、着手前にAPIキー取得が必要
