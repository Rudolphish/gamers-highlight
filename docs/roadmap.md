## Phase 2：展開判断

このフェーズで「他の友人グループにも展開するか」を判断する。判断材料：

- 自分の友人グループで実際に投稿・検索の習慣が定着したか
- 「あのスクショどこだっけ」という元々のペインが解消されたと言えるか
- 運用コスト（Supabase/R2/Vercelの無料枠内で収まっているか）

展開しない判断であれば、個人・身内用ツールとして磨き込みを継続する（Phase 3以降は保留）。

## Phase 3：マルチテナント化（展開する場合）

グループ機能の実装により、想定より前倒しで土台の大部分ができている。

- [x] Discord Botの自己導入フロー（サーバー管理者が自分でBotを招待・設定できるように）— マニュアルページに手順ガイド＋招待リンクを用意済み
- [ ] Botの常時稼働ホスティングへの移行（ローカルPC常駐 → Railway/Fly.io等）— PM2導入でローカル常駐の安定性は改善したが、ホスティング自体の移行は未着手
- [x] テナントごとのデータ分離設計 — グループ機能（`Group.guildId`で1グループ=1Discordサーバー）で実現済み
- [x] オンボーディングフロー（新規友人グループ向けのセットアップ導線）— グループ作成時のサーバーID入力＋マニュアルページで最低限は対応済み

## Phase 4：収益化検証（展開する場合）

EpicSnapで検討していた「保存数制限＋Stripeサブスク」型を叩き台にしつつ、Powderの事例（一般ゲーマー向け課金からの撤退）を踏まえて慎重に検証する。

- [ ] 料金モデルの仮説検証（フリーミアムか、コミュニティ管理者向けB2Bプライシングか）
- [ ] Stripe連携によるサブスクリプション管理
- [ ] 課金導線のUX設計（保存容量制限など、体験を損なわない形での提示）

一般ゲーマー個人への定額課金は懐疑的な材料が多いため、**コミュニティ運営者（Discordサーバー管理者）向けのB2Bプライシング**を優先候補として検証する。

## Phase 6：柱2「これから遊ぶゲームを考える」（長期ゴール）

**個人のウィッシュリスト/ライブラリ管理はSteam自体で完結するため、本アプリでは作らない。** 価値があるのは「グループで共有される」ウィッシュリスト/ライブラリ（このグループが狙っているゲーム、グループ内で今誰が何を遊んでいるか）。データ設計は`Group`単位（`GroupGame`のような新モデルを想定：groupId, steamAppId, status〈WISHLIST/PLAYING/BACKLOG/COMPLETED〉, addedBy, 関連Album（あれば）への参照）。**旧Phase 5にあった「プレイ状態管理」（プレイ中／クリア済み／積みゲーの分類）はこの`GroupGame`のstatus管理に統合済み**（個人単位ではなくグループ単位で管理する）。

- [x] データ設計：グループ単位のゲームリスト（`GroupGame`。ステータス管理〈プレイ中/クリア済み/積みゲー/ウィッシュリスト〉、Steam appId紐付け）— Albumとの関連付けは未実装
- [x] ステータスによる絞り込みUI（グループのゲームリストをプレイ中／クリア済み／積みゲー／ウィッシュリストでフィルタ）— グループ詳細ページに実装済み
- [ ] Steamジャンル検索（既存の`lib/steam.ts`の検索機能を拡張。ジャンル情報は`appdetails` APIから取得可能）
- [ ] サジェスト機能（まずは簡易ルールベースで着手：グループが過去に遊んだゲームのジャンル/タグから類似ゲームを提案）
- [x] ゲーム詳細ページの土台（`/groups/[groupId]/games/[gameId]`。タイトル・ステータス・Steamストアリンクのみの最小構成）
- [x] ゲーム詳細ページ：Steamレビュー表示（公開APIで取得可、APIキー不要）— 実装済み
- [x] ゲーム詳細ページ：現在の価格・セール状況表示（Steam公式APIで取得可、APIキー不要）— Phase 7から前倒しで実装済み（最安値/値動きグラフは引き続きPhase 7でIsThereAnyDeal APIが必要）
- [ ] ゲーム詳細ページ：関連YouTube動画表示（**要事前準備**：YouTube Data APIキーの取得）
- [x] アプデ情報のキャッチアップ（Steam News API。キー不要）— ゲーム詳細ページに最新3件表示。グループ内の複数ゲームを横断した一覧化は未実装
- [ ] グループ内プレイ状況の可視化（「今誰が何をプレイ中/積んでいるか」の一覧。[`ideas.md`](./ideas.md)参照）
- [ ] **ゲーム提案機能**：グループメンバーが「このゲームどう？」とゲームを提案できる。提案には「ゲームページ」（Steamストアへのリンク、関連YouTube動画、価格/セール情報）を表示し、他メンバーがリアクション（興味あり等）できる。一定の反応を集めた（または誰かが確定させた）提案は、グループの「やりたいゲームリスト」（`GroupGame`のWISHLISTステータス）に登録される
  - 前提：ゲームページの中身（Steamレビュー/YouTube動画は本Phase、価格/セール情報はPhase 7）に依存するため、提案機能自体はそれらが揃ってから着手するのが自然
  - データ設計：`GroupGameProposal`（groupId, steamAppId, proposedBy, createdAt）＋`GroupGameProposalReaction`（proposalId, userId, reactionType）を想定

## 柱2・3を進める上での論点

- 柱2・3は、現在の「友人グループ内スクショ整理ツール」という狭い立ち位置から大きく踏み出す拡張になる。vision.mdの「非ゴール」（周辺機能を広げすぎない）との兼ね合いは意識しつつ、**Phase 2の展開判断を待たずPhase 6（柱2）から着手する**方針とした（2026-08-07決定）。柱3（Phase 7）の着手時期は未定
- YouTube Data API・IsThereAnyDeal APIはいずれも無料枠はあるが、着手前にAPIキー取得が必要（Phase 6のYouTube動画表示・Phase 7の最安値表示のタスクに影響。それ以外のPhase 6タスクは先に進められる）
