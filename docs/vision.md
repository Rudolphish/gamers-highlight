# Gamer's Highlight - ビジョン・方向性

## 🎯 ゴール

Discordに流れていくゲームのスクリーンショット・クリップを、**投稿の手間を増やさずに**ゲームごとに自動整理し、後から迷わず辿り着けるようにする。

「あのスクショどこだっけ」をなくすこと自体がゴールであり、大きなSNSやプラットフォームを作ることは目的ではない。

## 🧩 コアペインと解決アプローチ

- 友人とDiscordで遊んだ際のスクショ共有は、時系列でしか流れないため後から探しづらい
- 特に1チャンネルに複数ゲームのスクショが混在すると、過去の投稿を探すのが困難
- **Discord Botによるハッシュタグ検知＋自動取り込み**が唯一無二の差別化要因。これにより「Discordに貼るだけ」で自動的に整理されたアルバムができる、という体験を実現する

## 👥 ターゲットユーザー（フェーズで変化する）

| フェーズ | ターゲット |
|---|---|
| 現在（検証中） | 開発者本人の友人グループ（4人程度） |
| 展開判断後 | 同様の少人数の友人グループ（数〜十数人規模のゲーミングコミュニティ） |
| 現時点では対象外 | 不特定多数の一般ゲーマー、eスポーツチーム、企業 |

## 🆚 差別化ポイント

- **Powder / Sizzle.gg / Framedrop** 等の既存サービス：ハイライト自動生成が主軸。Powderは一般ゲーマー向け課金から撤退した実績があり、一般ゲーマー相手の定額課金モデルには懐疑的な材料になっている
- **EpicSnap（本プロジェクトの前身にあたる旧構想）**：手動アップロードのみの汎用スクショ共有アプリとして、最初から広いターゲット・フリーミアム課金を前提に設計されていたが、初期開発段階で止まった
- **Gamer's Highlightの立ち位置**：Discordへの自動取り込みという明確なペイン解消に絞り、身内での検証を最優先することで、開発が迷走するリスクを避ける

## 📚 EpicSnapから得た教訓

過去に着手した類似構想（`F:\EpicSnap`）を振り返って、活かすべき点と繰り返さない点を整理する。

**活かす点**
- docsを役割ごとに分割する構成（overview / tech_stack / roadmap）は見通しが良く、本プロジェクトでも踏襲する
- 「保存数制限＋サブスク」のようなシンプルな収益化の型は、将来B2B/フリーミアムを検討する際の叩き台になる
- 「ゲーム別自動分類」「ハイライト自動生成」といった将来機能の方向性は、本プロジェクトのspec.mdの拡張性セクションとも一致しており、長期的な発展の道筋として引き続き有効

**繰り返さない点**
- 最初から不特定多数向け・フルスペック（Stripe課金、広告SDK、モバイルアプリ）を前提に設計しない
- コアの差別化要因（Discord自動取り込み）を確立する前に、周辺機能を広げすぎない
- 収益化モデルを検証前に確定させない（Powderの事例を踏まえ、一般ゲーマー向け定額課金は慎重に判断する）

## 🚫 非ゴール（現時点ではやらないこと）

- 広告SDK導入
- 汎用SNS連携（Twitter/X等への投稿連携）
- モバイルネイティブアプリ（PWA化程度は将来検討）
- 不特定多数へのオープンサインアップ（当面は招待制を維持）

詳細な技術仕様は [`spec.md`](./spec.md)、段階的な開発計画は [`roadmap.md`](./roadmap.md) を参照。
