# 読み込み中の表示を決めた過程（2026-10-22）

**いまの表示は候補 A「扇が開く」を、待ち時間で出し分ける形。** 実装は `components/layout/RouteLoading.tsx`
（出し分け）・`components/brand/BrandMark.tsx`（マーク）・`app/globals.css` の `.brand-mark`（動き）。
候補は全部 [`docs/design/loading/candidates.html`](./loading/candidates.html) で動くまま見られる。

## なぜ作り直したか

以前は画面を移るときに `loading.tsx` の骨格（灰色の箱）を出していた。Next.js 15 に上げたとき、
**`loading.tsx` のある画面で `router.refresh()` が数回に1回反映されなくなった**（CLAUDE.md「loading.tsx を置かない」）。
骨格は `loading.tsx`（Suspense の境界）でしか出せないので、読み込み中の表示ごと作り直した。
ユーザーがもともと作り直すつもりだったところに、favicon（M1）が決まった直後だったので、マークを動かす案になった。

## 候補

M1 の部品（奥の2枚の板・手前の光る板・「S」）に意味のある動きを付けた。

| 候補 | 動き | 評価 |
|---|---|---|
| **A 扇が開く** | 重ねた板（Staq）が広がって渡される（Share） | **採用**（ユーザーが実際のアプリでの動画を見て決めた） |
| B 「S」を描く | ネオン管が灯るように「S」が描かれる | 20px でもいちばん読み取れる |
| C ネオンが息をする | 形は動かさず光だけ強弱 | 動きを減らす設定の人向けに使っている |
| D 積み上げる | 板が1枚ずつ降りてきて重なる | いちばん賑やか。1周が長い |
| E 扇＋「S」 | A と B を同時に | 大きいサイズ向け |

## 出し分け

| 待ち時間 | 出すもの |
|---|---|
| 〜0.3秒 | 何も出さない。ほとんどの画面移動はここで終わり、毎回ロゴが一瞬出るとチカチカして遅く感じる |
| 0.3〜1秒 | 上の進行バー＋ロゴの横のマークが動く。前の画面はそのまま |
| 1秒〜 | 本文の場所だけ暗くして、中央にマーク＋ロゴ＋「読み込み中…」。左メニューと下のタブは押せるまま |

- 一度出したら最低0.4秒は出しておく（すぐ消えるとチラつく）。20秒で諦めて消す（返ってこないときに残り続けないように）
- 動きを減らす設定（`prefers-reduced-motion`）の人には、板を動かさず光の明滅だけ（候補 C）
- 読み上げには `role="status"` で「読み込み中」を伝える
- ロゴはスマホの上の帯・PC の左メニューとも「マーク＋ShareStaq」にした。左メニューを畳んだときは、以前の「SS」の代わりにマークだけ

**Suspense を使っていない。** 移動の始まりは内部リンクのクリック、終わりは URL の変化で、ブラウザ側だけで判定している
（以前の上の進行バー `RouteProgress` と同じ判定）。Next.js 15.5 の不具合に当たらないため。
そのぶん、`router.push()` など**リンクのクリックを通らない移動では出ない**（以前の進行バーも同じ）。

## 入れなかったもの

- **アプリを開いた最初の大きな表示（スプラッシュ）。** サーバーで描いた画面がそのまま届くので、普通に開いたときは出す間が無い。
  出せるのはホーム画面に追加したアプリとして開いたときだけで、別の仕組み（iPhone の起動画像）になる
