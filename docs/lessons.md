# 進め方の記録

**`CLAUDE.md` との違い**: あちらは「このコードを触るときに知っておくべきこと」。
こちらは「**作業の進め方でやらかしたこと**」——確認の仕方、道具の使い方、判断の順序。
コードを読んでも絶対に分からないので、書き残さないとセッションが変わるたびに同じ穴に落ちる。

`CLAUDE.md` と同じ方針で、**一般論は書かない。** ここに載っているのは全て一度やらかしたこと。
「〜すべき」で終わる項目は書かない。**何が起きて、どう間違えたか**を残す。

## 確認

### テストは「落ちること」を見るまで書けたことにならない

キャッシュ無効化のテスト（F68）が通ったので直ったと判断したが、**通った理由が
別のテスト（F67）がその前にタグを流していたから**だった。順序を入れ替えたら落ちた。
実装から無効化を消しても通るテストは、何も確認していない。

以来、修正のテストを足したら**修正を外したビルドで実際に落ちることを確認**している。
手間は「ビルド1回＋実行1回」。この確認を省いた回は必ず後で「実は効いていなかった」が出ている。

**落ち方も見る。** アルバムの「追加」ボタンを壊したら `click` が例外になり、**70件ぶんの
表がまるごと消えた**。無いときは以降を「未確認」として記録して抜ける。**入口ごとに
ガードを置くのでは足りない**（Steam連携の付け替えで3回踏んだ）。クリックの連鎖は
**ブロックごと try/catch で包む**。

**壊したのに通ったら、通った理由を測る。** ドロワーの背景タップのテストが、背景の処理を
消しても通った。覆えていない背景をすり抜けたクリックが本文のリンクに当たり
**遷移のついでに閉じていた**のが理由で、ドロワーがヘッダーの帯の中（高さ74px）にしか
出ていないという**本物の不具合も一緒に見逃していた**。

**裏返しも使える。外しても落ちない対処は入れない。** 原因の見立てで足した2つ
（レールの `z-30`、スワイプ後の click を捨てる処理）は、外してもテストが全部通った。
どちらも**別の本当の原因**（`pointer-events-none`、ブラウザの戻るジェスチャ）を
取り違えて足したもので、後者は入れたことで「次のタップで閉じられない」を新しく作っていた。

**「2回目だけ落ちる」を見た瞬間に原因を決めない。** B108 が通しの2回目だけ落ちたとき
「座標が下部パネルに当たっている」と判断して直したが**次も同じ場所で落ちた**（備考の実測は
「その点に居るのは overlay」）。本当の原因は、払った直後のタップにブラウザが
**click を一切合成しない**こと（0ms・400msは0件、800msで1件）。**先に測れば1周で済んだ。**

### 「そうなるはず」の初期状態で試すと、直っていなくても通る

「投稿したアルバムが先頭に来る」テストを**新しく作ったアルバム**で書いた。作ったばかりの
アルバムは何もしなくても先頭に来るので、**修正を外したビルドでも通った**。先に自分の
アルバムを下に沈めてから投稿する形に書き直したら落ちるようになった。
**期待する結果と同じ初期状態から始めない。**

### 手元のシェルに読み込んだ環境変数に、テストが寄りかかる

Botの遡り取り込みのテストで `apps/bot/dist` を読み込んだら、**CIだけが落ちた**
（`undefined/api/discord/ingest`）。モジュールは**読み込んだ瞬間に**
`INTERNAL_API_BASE_URL` を掴むが、CIにその変数は無い。手元では `.env.local` を
読み込んでいたので通っていた。**テストが要る環境変数はテスト自身で用意する。**

### 単体で通るテストが、通しで流すと落ちる（逆も同じ）

アルバムの並び替えのテストを表示順の**位置**で書いたら、単体では通ったが `run-all.mjs` で
落ちた。**flows が同じグループにアルバムを1件作る**ため、通しだけ位置がずれる。
スイートは同じDBを順番に使うので、**後ろのスイートは前のスイートが足したデータを見る**。
自分で仕込んだデータの**相対順序**だけを見る。枚数のような値も**絶対値で断定しない**。
**seedのデータも「残っている」前提では使えない**（flowsが提案を昇格させてPENDINGから
外れ、通しだけ落ちた）。**要るデータは自分で作る。**

逆もある。**ブラウザスイートは単体で流すと落ちる**（前のスイートが作る状態に依存する）。
壊して確認するときも `run-all` で流す。単体だと**実行が落ちても前回の結果がそのまま返る**
（実際に古い表を読んで誤読した）。

### 「1箇所に集約した」は、集約前の形を全文検索するまで終わっていない

アルバムのカバー選びを `lib/albumCoverPolicy.ts` に集約したとき、**画面2箇所だけを直して
API（`/api/groups/:id`）を見落とした**。直した2つは「いま開いていたファイル」で、3つ目は
探しにいかなければ出てこない場所だった。集約したら**集約前の形
（`photos: { ... take: 1 ... }`）を全体検索して残りを潰す。** 通さない箇所には印を書いて
宣言する。**その形を見ている道具も一緒に動かす**（`lib/uploadClient.ts` へ出したとき
`audit-media-limits.mjs` が古い場所を見ていてCIが落ちた）。

### 文字列一致でソースを判定すると、コメントに当たる

写真リアクションのAPIが意図的にキャッシュを無効化しない理由をコメントに書いたら、
**そこに含まれる `cacheTags` という単語**に2つの仕組みが反応した（F82が落ち、
`audit-invalidation.mjs` もCIを落とすところだった）。どちらも**実際のimport文と呼び出し**を
見る形に直し、「意図的に無効化しない」と宣言する印を足した。

### 結果の表を作る側は、同じ情報を2箇所に書いた時点で壊れている

ブラウザスイートの表で2回踏んだ。どちらも**判定は正しいのに表が信用できなくなる**壊れ方で、
成功パスでは出ないため自分では気づけず、自動レビューで出た。

- **項目名を添字で引いていた**（`EXPECTED[7][1]`）。項目を1つ挟んだら**B106 に B108 の
  名前が入り、同じ名前の行が2つ並んだ**。
- **溜め先を `rows` → `localRows` に変えたのに、catch 節の「記録済みか」の判定
  （`rows.some(...)`）を直し忘れた。** 途中で落ちると記録済みの行まで「未確認」で
  二重に積まれる。温床は**項目名を記録側と catch 側に二重に書いていたこと**。

いまは3ブロックすべて `EXPECTED`（IDキー）＋`recorded`＋`rec(id, ...)` に揃えてある。

### 落ちたままの結果ファイルをコミットしない

`docs/test-results.md` は `run-all` が書き出す。**流し直す前にコミットするとNGの表が入る。**
実際に「NG 1件」の表を入れたまま、コメントには「確認済み」と書いて食い違った。

**壊して確認した直後に `git checkout -- docs/test-results.md` で戻す。** 3周つづけて
ここで止められた。流し直しは数分かかるので、その間にターンが切れると**自動レビューが
壊し確認の表（備考に「catch経路」など）を読んで毎回FAILを出す**。

### 画面に重なりがあるテストは、見る範囲を絞る

Lightbox の❤️を数えたつもりが、**背後のグリッドに残っているボタンも一緒に数えていた**
（重ねて表示するものは前のDOMが消えない）。`document` 全体を数える判定は、たいてい違う。

### 1回しか実行しないと、2回目に壊れるものが見つからない

`unstable_cache` は値をJSONで保存するため、Prismaの `Date` が2回目からISO文字列で返る。
`capturedAt?.toISOString()` は**キャッシュヒットの回だけ**落ちる（F62b・F64b は必ず2回開く）。

**テスト自身が状態を残す側になることもある。** ブラウザスイートを同じDBに2回流したら3件
落ちた（❤️を押したまま終わっていた）。**CIは毎回まっさらなDBなので絶対に出ない**。
書き換えるテストは終わったら戻し、CIに載せる前に**2回連続で流す**。

### 確認の道具が壊れていても、結果は「0件」で普通に返ってくる

**どれも「アプリが壊れている」ようにしか見えず、疑う先を間違えた。**

- **後片付けをDB直で書いた（F96・F97）。** `db.photo.deleteMany` はAPIを通らず
  `invalidateAlbumPhotos` が呼ばれないので、消えた写真がキャッシュに残り、次に走る
  ブラウザスイートがそれをクリックして落ちた（症状は「❤️が効かない」）。決め手は
  `context.on("response")` で4xxを拾ったこと。→ **作ったデータは同じ経路で消す。**
- **cronのルートは `fetch-stub` を通らない**（手動送信は通る）。→ DBに残る記録で見る。
- **Reactは隣り合うテキストを区切る。** `{emoji} {count}` は `📷<!-- --> <!-- -->3` になり
  `/📷 (\d+)/` が当たらない。→ **1つの文字列として描く。**
- **正規表現で `{...}` を拾おうとした。** `audit-cover-policy.mjs` が `orderBy: { ... }` を
  含む書き方に当たらず**1件取りこぼした**。→ **入れ子は括弧の対応を数える。**
- **「見えている」の測り方を3回間違えた。** `isVisible()` はビューポート内かを見ないので
  **上に抜けたリンクも「見えている」**→ `boundingBox()` の y。`opacity` と矩形は
  切り取られても「出ている」と答える → `elementFromPoint`。ただし**それは
  `pointer-events: none` の要素を飛ばす**ので、**直っているのに落ち続けた**
  （測る間だけ `pointerEvents` を戻す）。

**環境の健全性を先に確かめる。** そこが壊れていると、壊して確認する手順ごと無意味になる。

### 根拠にならないものを根拠にしない

- **測っていない説明は憶測。** 自動レビューが飛んでいた件で「コンテナの再起動のせい」と
  書いてPRに載せたが間違いだった（`getPendingCommits` が起点を辿れず黙って引き直していた）。
  モバイル対応でも「内側スクロールでURLバーが引っ込まない」を主犯として出したが、
  **その div は一度もスクローラになっていなかった**。どちらも読んだだけで測っていなかった。
- **コメントは動作の証拠ではない。** `refresh/route.ts` の「埋まっている項目は引き直さない」は
  実装がそうなっておらず（`need` 未渡し）、半月気づかなかった。
- **ユーザー向けの説明も証拠ではない。** マニュアルの「アルバム名は変更できます」「30秒まで」は
  **前者は画面に入口が無く、後者は判定に値が渡っていなかった**（APIには実装があった）。
  **説明の側から実装を辿る。**

## 自動で走る仕組み

### 「走らなかった」が見えない仕組みは、壊れていても気づけない

自動レビューは新しいブランチの最初のコミットを毎回飛ばしていたが、**飛ばしたことを
`console.error` に出すだけで台帳にもログにも残していなかった。** 「PASSした」のか
「走らなかった」のかが区別できず、6本が未レビューのままマージされていた。
**沈黙を成功と解釈できる状態を作らない。**

### 可視化のために足した記録が、判定にも使われると逆効果になる

「見送り」を台帳に `SKIP` 行として残すようにしたが、台帳は「レビュー済みのコミット一覧」を
作るのにも使われている。**`SKIP` をそこに数えると、見送った瞬間にそのコミットが恒久的に
レビュー対象から外れる。** 記録を足すときは**その記録を読んでいる処理を全部洗う。**

### 実行中のプロセスが書くファイルを、バックアップから復元してはいけない

台帳をバックアップして復元していたら、裏で動いていた後追いレビューの追記を上書きし、
**#40 のレビュー記録が消えた**。並行して動かすなら**差分で戻す**か、別ファイルに向ける。

### 手順を決める前に、禁止されている操作を見る

`git push --force-with-lease` を3回試して3回とも弾かれた。原因は `.claude/settings.json` の
deny にある `Bash(*git push*--force*)`。拒否は理由を伝えないため「ユーザーが渋っている」と
読み違えて往復を2回挟んだ。**止まる層は2つあり、事前に見られるのは片方だけ。**

- **設定（`.claude/settings.json` の `deny`）**: force push・`prisma db push`・`rm -rf`・
  本番デプロイ。**見られる。手順を決める前に読む**
- **認証（プロキシ）**: `git push origin --delete` が **HTTP 403**（GitHub MCP にも削除ツールは
  無い）。見られないので一度試して駄目なら手順を渡す。`git push` は ref の削除に失敗しても
  「Everything up-to-date」と出す（`-v` を付けるまで403が見えない）

## ローカル環境

### `pkill` は親だけ殺して子が生き残る

`pkill -f "next start"` で死んだのは pnpm のラッパーだけで、`next-server` の子が3000番を
掴んだまま残った。新しいサーバーは `EADDRINUSE` で起動に失敗し、**テストは古い（修正済みの）
サーバーに当たって 0 NG を返した。** サーバーを入れ替えるときは、
**ポートが空いたことを確認してから**起動する。

```bash
ps aux | grep next-server | grep -v grep | awk '{print $2}' | xargs -r kill -9
lsof -ti :3000    # 何も出なければ空き
```

（以前ここには `ss -ltn` と書いてあったが、**`ss` も `netstat` もこのコンテナには無い**。
実際に踏んで `command not found` になった。）

### 本番ビルドはコードを変えても勝手に入れ替わらない

`tools/local-test` は `next build && next start` で確認する（`dev` だとNext.js自身の
エラーオーバーレイでアプリ側のエラーバウンダリが見えない）。**ソースを直しただけでは
反映されない。** 組み直すまで見ているのは前のコードの挙動。

**対象はWebだけではない。** Botの遡り取り込みのテストは `apps/bot/dist` を読むので、
`apps/bot` の組み直しを忘れて**関係ない回で落ち続けた**。dist を読むテストを足したら、
その dist を作る手順も同じところに足すこと。

### リポジトリルートで `npm install` を実行しない

pnpmワークスペースなので `node_modules` が 182 → 18 に刈り込まれて動かなくなる
（戻すには `pnpm install` と `npx prisma generate`）。

### コンテナ再作成でPostgreSQLが止まる（`pg_ctl` はPATHに無い）

2回踏んだ。ソケットが `/tmp` に残るので `pg_isready` は「no response」。
`/usr/lib/postgresql/16/bin/pg_ctl` を**postgresユーザーで**叩き、残ったソケットを
先に消す。データは消えていない。

## レビュー

### 自分で書いた直後のコードは、自分では見えない

飛ばされていた7件を後から掛け直したら **6件PASS・1件FAIL** で、FAILは「コメントと実装が
食い違い、クォータ枯渇を悪化させる」という実害のあるものだった。どれも自分でテストを
通してマージしたコードだった。モバイル対応でも**自分が足した1行でPC幅のツールチップを
切っていた**のをレビューで指摘された。
**マージ前に `node .claude/hooks/review-status.mjs --range` で確認すること。**

### 台帳の列は複数値を持ちうる

`review-status.mjs` を作ったとき、台帳の `commits` 列を単一SHAとして扱った。実際は
まとめてレビューすると `;` 区切りで複数入る。**レビュー済みのコミットが軒並み
「未レビュー」に見える**という、この道具の信頼を落とす一番まずい壊れ方をした。

書く側の形式は、読む側を書く前に**実物を見る**。

## CI

### サードパーティのactionは落ちる。標準で足りるなら使わない

CIの最初の実行が、テストを1つも動かさないまま両ジョブとも落ちた。原因は
`pnpm/action-setup` のダウンロードが **429**。**同じ落とし穴が残る**ので `corepack` に
替えた。**外せる外部依存は外す。**

## 書き足すルール

- **足すのは「一度やらかしたこと」だけ。** 予防的な心得は書かない。増えるほど読まれなくなる
- 自動レビューが **FAIL** を出したら、直したあとにここへ1項目足す。
  コードの落とし穴（この関数はこう呼ぶ、この順序で書く）なら `CLAUDE.md` の方へ
- **何が起きたか**を具体的に書く。「〜に注意」だけの項目は、次に読んだとき判断に使えない
- 同じ話が2箇所に増えたら統合する。長さではなく**読まれることが価値**
- **8192文字**を超えるとセッション開始時に警告が出る。出たら古い項目を畳む
