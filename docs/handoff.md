## 2. 総合テストの結果（2026-08-16）

ローカルにPostgresと模擬R2を立て、外部APIをスタブして**本番ビルドのまま**通しで確認した。
手順と一式は [`tools/local-test/`](../tools/local-test/README.md) に置いてある（次回は組み直さなくてよい）。

| 観点 | 件数 | 結果 |
|---|---|---|
| 全ページ × 未ログイン＋3役割 | 30パス | ステータス・リダイレクトとも期待どおり |
| APIの権限 | 59ケース | 全て期待どおり |
| 主要導線（アップロード/招待/提案/ゲーム追加/Discord取り込み/エラー通報/cron） | 52ケース | 全て通過 |
| 実ブラウザ（Chromium）で19ページ | — | 例外・ハイドレーションエラーなし |
| 外部APIが全滅した状態 | 5ページ | 500にならずページは描画される |

**見つかった不具合は1件**（このブランチで修正済み）。

- `/albums/[albumId]` に権限チェックが無く、**ログインしていればURLを知っているだけで
  他人のグループのアルバム（写真・メンバー名）が見えていた**。
  同じリソースの `GET /api/albums/:id` は最初から403なので、APIだけ見ていると気づけない。
  再現は `tools/local-test/repro-album-leak.mjs`、修正後の確認は `verify-album-access.mjs`。
  背景は `CLAUDE.md` の「ページはAPIの権限判定を通らない」に追記した。

副産物として確認できた（＝直す必要が無かった）こと:

- グループ／ゲーム詳細／提案詳細のページは権限チェック済み。アルバム一覧・未分類・写真検索も
  クエリの時点で自分の見える範囲に絞られている
- HowLongToBeatへ渡すタイトルが**英語名**になっている（日本語名だと必ず0件になる件）
- 署名付きURLに `x-amz-checksum-` が入らない。`content-length` は署名対象に入っている
- 招待リンクの回数消費・取り消し・期限切れ、Discord取り込みの重複防止

### まだ直していない小さな引っかかり

- `next.config.js` の `outputFileTracingRoot` が**トップレベルにあるためNext.js 14では無視される**
  （起動時に `Unrecognized key(s) in object: 'outputFileTracingRoot'` が出る。14では
  `experimental` の下が正しい）。今のところビルドもデプロイも通っているので触っていない。
  `CLAUDE.md` の「過去に壊した実績があるもの」に載っている項目なので、動かすなら単独で。

## 4. 直近で入れたもの（この2日分）

### 招待リンク（#19）

グループ画面から発行するリンク。未登録の相手でもDiscordログインだけで
「許可リスト登録＋グループ加入」まで通る。有効期限・使用回数の上限・取り消しは必須要件。

**設計上いちばん重要な点**: 回数の消費は**グループ加入時ではなくログイン時**。
`AllowlistEntry` を作る＝アプリへの恒久的なログイン権限を渡すことなので、そこで数えないと
「1回限り」のリンクで複数人がログインできてしまう（詳細は `CLAUDE.md` の「権限」）。

### スクショからのゲーム自動判別（#21〜#26）

ファイル名から Steam の app ID を読んでタグとアルバムを決める。

**ファイル名の形は保存元で3通りあり、ゲームが分かるのはDL形式だけ**（`CLAUDE.md` 参照）。
普段の使い方（クリップボード貼り付け）では手掛かりが残らないため、
**判別できなかった投稿にはBotが「どのゲーム？」と聞く**。候補は直近3件＋自由入力で、
自由入力はSteam検索→ゲーム登録→アルバム作成まで一気に通る。

### 管理者ページの拡張（#20）

`/admin` に「ユーザー」（アクティブ率の計測）と「招待リンク」（全グループ横断の監査）を追加。
招待リンクの監査では「未加入のまま権限あり」の人数を強調している。

### アップロードの修正（#34, #35）

- グループ共有アルバムへの投稿が403になっていた（権限判定の穴）
- **R2は署名付きPOSTに非対応**。501が返るがCORSヘッダーが付かないため、
  ブラウザ上はCORSエラーに見えていた。署名付きPUTに切り替えて解決

## 6. セッションの作り方（gitが使えない場合はここ）

git 操作ができるのは、**claude.ai/code からリポジトリを指定して作ったセッション**だけ。
その場合だけ次が自動で用意される。

- リポジトリのクローンと、**プロキシ経由のgit認証**（`HTTPS_PROXY` が経路上でトークンを差し込む。
  `GITHUB_TOKEN=proxy-injected` となっており、トークンの実体はどこにも置かれていない）
- GitHub MCP ツール（PRの作成・マージ）
- コミット署名鍵

**リポジトリを指定し忘れて作ったセッションでも、後から追加できる。**
ただし「追加して」だけだと**何に追加するのか伝わらず聞き返される**ので、こう頼む。

> `add_repo` で `owner=Rudolphish` `repo=gamers-highlight` を `access=push` で追加して、
> 案内されたコマンドでクローンし、`register_repo_root` まで済ませて。

- **`access=push` を明示する。** 既定は `read` で、取得はできても**pushとPR作成ができない**
- `add_repo` は登録するだけなので、**クローンは別に実行する**必要がある
- **`register_repo_root` を忘れない。** 呼ばないと `CLAUDE.md` が読み込まれず、
  ここに書いた落とし穴の知識が効かない

「そんなツールは無い」と言われたら、そのセッションはリモート実行環境ではない。
claude.ai/code からリポジトリを選択して作り直す。

ローカルCLI（自分のPCの `claude`）はこの仕組みを持たない。素直に `gh auth login` か
SSH鍵で認証する。真似る必要は無い。

切り分けるときは次を見る。

```bash
git remote -v
env | grep -i https_proxy      # 空ならプロキシが無い＝この仕組みの外
git ls-remote origin | head -3 # 認証が通っているか
```

## 7. 開発環境の再現

サンドボックスに本番のDBは無いので、**ローカルにPostgresを立てて検証している**。
次のセッションでも同じ手が使える。

```bash
# Postgres 16 を postgres ユーザーで起動（/tmp にソケット、5433番）
setsid su postgres -c "/usr/lib/postgresql/16/bin/pg_ctl -D /var/lib/postgresql/ghdata \
  -o '-p 5433 -k /tmp' -l /tmp/pg.log start"

# 接続先
DATABASE_URL="postgresql://postgres@localhost:5433/gh?host=/tmp"
```

- **`prisma db push` は権限で失敗する**ので、スキーマ変更は
  `prisma migrate diff` の出力を `psql` に流して当てている
- 本番ビルドで確認する（`next build && next start`）。`dev` だとNext.js自身の
  エラーオーバーレイが出て、アプリのエラーバウンダリの挙動を確認できない
- ログインは `dev-login` が本番ビルドで無効なため、**NextAuthのJWTを直接発行**して
  Cookieに入れている（`NEXTAUTH_SECRET` を合わせるだけ）。トークンは1時間で切れるので、
  Playwrightで「0件」になったらまず再発行を疑う
- 外部APIは `globalThis.fetch` を差し替えて確認する。R2は「PUTは受けてPOSTには501を返す」
  模擬サーバーを立てると、本番と同じ壊れ方を再現できる

**この手順一式は [`tools/local-test/`](../tools/local-test/README.md) にある。**
シード・スタブ・模擬R2・権限マトリクスまで揃っているので、次からは手で組み直さなくてよい。

## 8. 進め方の約束

このリポジトリでの作業は次の形で回している。

1. **ブランチを切る**（`claude/<内容>`）。master に直接コミットしない
2. **バグは直す前に再現させる**。再現した証跡をPRの説明に載せる
3. PRの説明には**判断の理由と、確認できなかったこと**を書く
4. マージはユーザーの指示を待つ
5. スキーマを変えたら、PRに **`prisma db push` が必要**と明記する
   （Vercelはコードしかデプロイしないため）
